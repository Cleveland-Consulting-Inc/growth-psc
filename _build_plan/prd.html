Growth.PSC

A web-based proposal platform at growth.premiersportscamps.com that lets Premier Sports Camps administrators generate, manage, and share branded pitch decks with college coaches. Each proposal lives at its own URL (e.g., /yale/), is protected by a 4-digit PIN, and can be taken offline at any time. Admins get a dashboard to create new proposals from a template, customize content without touching code, and monitor who has viewed each proposal.

Nuxt 3 Vue 3 Tailwind v4 SQLite Vercel

What the app does

  • Proposal Generator

    Create a new university pitch in seconds — enter a name and slug, set a PIN, and the proposal is instantly live at its own URL.

  • Template Management

    Edit the master template from the admin panel. Changes apply only to future proposals — existing ones are frozen.

  • PIN-Gated Access

    Coaches must enter a 4-digit PIN before viewing a proposal. Wrong PIN shows an error; correct PIN grants session access.

  • Proposal On/Off Toggle

    Take any proposal offline instantly. Coaches see a "not available" message; content is preserved and the proposal can be re-enabled at any time.

  • Admin Dashboard

    A central list of all proposals with status, URL, PIN, view count, and quick-action controls.

  • Access Logging

    Every visit attempt is automatically logged with IP, browser/device, timestamp, and whether the PIN was correct.

  • Admin Content Editor

    Edit any proposal's text fields — headings, body copy, stats, contact info — from the admin panel without touching code.

Already provided by Nuxt 3 starter

  • Page routing
  • Server API routes (Nitro)
  • Vue 3 reactivity
  • Tailwind v4 styling
  • Vercel deployment pipeline
  • Server-side middleware support

Out of scope (v1)

  • Coach-facing interaction — No contact forms, reply buttons, or comment threads. The proposal is read-only for the coach.
  • Email / notification system — No automated emails when a coach views a proposal. Dashboard is checked manually.
  • Multiple admin users / roles — Single admin login only. No team accounts or permissions.
  • PDF export — No built-in PDF download. Browser print-to-PDF works if needed.
  • Advanced analytics — No time-on-page, scroll depth, or heatmaps. IP, browser, and timestamp only.
  • Proposal expiration dates — No auto-expire. Taking a proposal offline is always a manual admin action.
  • Custom domain per proposal — All proposals live under growth.premiersportscamps.com/[slug]/.
  • CMS media library — Images are part of the template. No drag-and-drop media management in v1.
  • IP geolocation — Raw IP address and browser string only. No city/state/country lookup.

Data model

What the app needs to remember.

Proposal

slug The URL path (e.g., yale) — unique per proposal
university_name Display name shown in the admin panel (e.g., "Yale University")
pin The 4-digit code coaches must enter to view the proposal
status Whether the proposal is live or offline
content All editable text fields for this proposal — a snapshot taken from the template at creation time
created_at When the proposal was created

Related to · AccessLog (one Proposal has many AccessLogs)

Template

version Increments each time the template is saved
content Default values for all editable fields — what new proposals start from
updated_at When the template was last saved

Note · Only one active template exists at any time. Proposals copy its content at creation and then own their own copy independently.

AccessLog

proposal_id Which proposal was accessed
ip_address The visitor's IP address
user_agent Browser and device string
pin_correct Whether the PIN entered was correct (yes/no)
timestamp When the visit occurred

Related to · Proposal (each AccessLog belongs to one Proposal)

Milestones

1

Backend & Admin

Establishes the full foundation — Nuxt 3 project, SQLite database, Vercel deployment, subdomain — and delivers the complete admin experience: template management, proposal creation, content editing, live/offline toggling, the dashboard list, access logging, and per-proposal log viewer.

What gets built

  • Nuxt 3 project scaffolded with Tailwind v4, SQLite database, and deployed to Vercel with growth.premiersportscamps.com pointed at it
  • Admin panel with password-protected login (single admin account)
  • Master Template editor — view and save all editable content fields, with last-updated timestamp and confirmation before save
  • Proposal Generator — form to enter university name, URL slug (auto-suggested), and 4-digit PIN; creates proposal and lands on its edit page
  • Per-proposal Content Editor — plain-text fields for all editable content, saved independently per proposal
  • Live/offline toggle on each proposal — instant, no confirmation needed
  • Admin Dashboard — table of all proposals sorted newest-first, showing name, slug, status, PIN, view count, and action buttons
  • Per-proposal Access Log viewer — timestamp, IP, browser string, PIN correct/incorrect, sorted newest-first

Not in this milestone

  • Coach-facing public proposal pages (that's Milestone 2)
  • PIN entry screen and session handling
  • Offline "not available" page shown to coaches

Done when: An admin can log in, edit the master template, create a new proposal for a university, edit its content, toggle it offline and back on, view the dashboard list, and see a per-proposal access log — all from a browser pointed at the deployed Vercel URL.

2

Public Proposal Pages

Delivers the coach-facing side of the platform: PIN-gated proposal pages at /[slug]/, session handling, the offline state, and access log writes on every visit attempt.

What gets built

  • Dynamic proposal route at /[slug]/ that resolves to the correct proposal
  • PIN entry screen with Premier Sports Camps branding, 4-digit input, and submit button
  • Correct PIN grants session access and shows the full rendered proposal; session persists until browser is closed
  • Wrong PIN shows an error message; coach can try again with no lockout
  • Offline proposals show a "not currently available" message instead of the PIN screen
  • Every visit attempt (PIN correct or not) is written to the AccessLog automatically
  • Proposal page renders all editable content fields from the proposal's saved content using the HTML pitch-deck design from the original template

Not in this milestone

  • Coach interaction (forms, replies, comments)
  • PIN lockout after failed attempts
  • Email notifications on view
  • IP geolocation enrichment

Done when: A coach can visit growth.premiersportscamps.com/yale/, enter the correct PIN, and see the full pitch deck; an incorrect PIN shows an error; an offline proposal shows the unavailable message; and the admin dashboard reflects each attempt in the access log.
